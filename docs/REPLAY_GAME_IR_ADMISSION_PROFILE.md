# Exact, diagnostic-only Go published Game IR admission — Epic #202 / #467

The preinstalled Pixi v1.0 runtime creates score=0 and emits `game_start` followed by `scene_entered` at launch. An `add_score` action executes `state.score += Math.trunc(action.value ?? 1)`. Even a syntactically valid `gameir.Document` can contain physics, timers, collisions, entity targeting, authored shell rules, float/string predicate coercion and side effects that a future Go scalar-only worker cannot reproduce.

This **private, unexported** `supportedPublishedIRProfile` first executes `gameir.Validate`, then admits an intentionally tiny `go-scalar-start-score-v1` subset **only as a preflight decision**. It requires canonical Game IR 1.0; no capabilities, shell, non-semantic metadata, assets, inputs, world layers or entities, exactly one inert scene without gravity, zero environment mutations, max eight `game_start` only unconditional rules, max eight explicit bounded signed integer `add_score` actions per rule and zero other action fields. These inputs can be decoded from genuine immutable Game IR, but fabricated in-memory Go structs are NOT publisher authorization. All other cases reject with versioned reason and no capability; malformed IR is separately marked invalid. The exact integer range and action budget keep resulting additions far inside IEEE-754 exact integer bounds.

The current reducer is not yet a full server worker, event/tick scheduler, run trace, seed, outcome or attestation. The preflight cannot independently verify that a player pressed a button, ran to a win, or produced a trusted score. The minimal start-rule path is grounded in the **preinstalled Pixi source**, but this ticket does not pretend an original browser vs Go golden run has been executed. Before parent #428/#382 can use this profile to issue actual verdicts, implement a separately independently tested fixed-tick Go reducer, same-tick action-order golden fixtures, published-package canonical full-digest checks and server-owned replay grants. Add profiles only through a versioned, source-reviewed capability release. Never silently coerce JSON strings, execute physics on a mock state, or treat unsupported conditions as false.

The Go tests cover a minimal Game IR base, two ordered positive/negative score rules, mutation of every gameplay-bearing category (input, physics scene, timer, collision, scene event, predicate, entity, shell, bounded action values), and distinguish invalid/unsupported. No public HTTP, rank, score, verified-state writes, native GPU evidence or Apple review certification.
