# Runtime Epic #202 — Browser result UI must not elevate untrusted provisional ranks (#443)

The shipped browser Pixi runtime embedded in iPhone/iPad WKWebView used to append **"Leaderboard: #N this week (unverified)"** whenever a run-submit response included any truthy numeric rank. A numeric leaderboard position can still suggest a genuine contest standing even with an ambiguous parenthetical. The legacy submit API accepts browser-provided score/seed/inputs and returns a **provisional** position without server-owned replay attestation.

A preinstalled **pure presentation guard**, `runtime-result-provenance.mjs`, now emits only an explicit `Provisional leaderboard position #N this week (unverified)` for positive bounded integer ranks under a declared provisional scope. A legacy result missing `rankingScope` is also treated as provisional, never authoritative. Unknown/verified-only scopes, malformed numbers, negative, zero, decimal, numeric strings and extremely large rankings render **no** placement. Even an inconsistent/forged `verified:true` on a provisional response cannot change the label into a verified rank.

The previous native notification only checked `data.verified === true`. The guard now requires `verified:true, attested:true, rankingScope:verified_only, evidenceStatus:verified` plus a bounded nonempty run ID **before it requests** the existing native verified-result lookup. These browser-visible flags do not constitute proof themselves; the native app must independently fetch and authorize the run and verify a genuine server-only attestor verdict. The current backend does **not** issue that verdict, so an ordinary provisional client run cannot trigger a native verified result.

The pure unit test suite covers valid and invalid rank types, old backend responses, claimed verification with incompatible scope, and valid/invalid native lookup hints. It is included in the existing Playability Node tests. A narrow Go embed route serves this preinstalled module with `nosniff`; creators cannot upload new scripts. The actual Game IR, replay recorder, game physics, run persistence and scores are unchanged.

**Senior game-engine architect challenge:** This is truthful **presentation** of one client score; it does not remove the existing vulnerable provisional default board, deploy server-owned replay #382/#429, or migrate native/HTML5 leaderboard screens to the safe verified-only read API #441. Parent security #402 and Epic #202 remain OPEN. Do not equate pure Node or browser CI with physical iPhone/iPad compositor/thermal acceptance. Rollback is limited to the trusted module, embed route, Pixi result copy, Node tests and this doc. Merge only after all six required exact-head CI jobs succeed.
