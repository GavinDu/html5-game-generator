# Strict bounded Go start-score diagnostic — Epic #202 / issue #475

This **private** Go reducer accepts only `supportedPublishedIRProfile(doc)`'s prior versioned `go-scalar-start-score-v1` declaration. It starts a fresh score at zero and traverses validated `game_start` rules, then each explicit bounded integer `add_score` action, in authored order. It computes a SHA-256 over an ASCII transcript with a profile/version header and per-step rule index, action index, authored rule ID, score delta and resulting score. Unlike the final score, the trace hash changes when +3 and -2 authored events are reversed.

The common fixture `internal/attestation/testdata/start_score_ir_v1.json` is read by (1) Go `gameir.DecodeAndValidate` and `reduceStartScoreDiagnostic` tests and (2) Node `tools/playtest/start-score-diagnostic.test.mjs`, which imports the **preinstalled renderer-independent** JS `conditionsMet` / `ruleMatches` and executes the same admitted pre-tick rule/action behavior. Both independently compare the pinned trace SHA-256 `9751d51614b4eb1b9bf8f03d155b8526c4f21f116b38d9af90b7ef6346af855d`, total score 1 and two ordered actions. Fresh-start determinism, authored-order permutations, negative and zero score, invalid IR, unsupported input/collision/timer/terminal/float/numeric string/scene branches, and nonmutation are covered.

**Crucial non-claim:** this is NOT the running PixiJS interpreter, a real Chromium/WebKit game boot, a full fixed-tick scheduler, replay attestation, or an independent verified score. JS source-comparator conformance does not prove what Pixi produced in a real play session. [Issue #469](https://github.com/GavinDu/html5-game-generator/issues/469) remains open for *genuine unmodified* minimal Game IR execution in Pixi, browser screenshot/probe evidence, restarts, and matching Go traces. If a supposedly admitted minimal Game IR cannot boot on the actual renderer, the versioned preflight must be narrowed/disabled. For real input traces, the schema-v2 semantic adapter #427, fixed-tick Go worker #428, server-owned replay #382, issuance #457, and verified-only ranking #402 are separate prerequisites.

There are **no new public endpoints, browser-asserted success flags, Score/Verified writes, native iPhone/iPad rendering changes or trusted verdict claims**. A caller can fabricate a valid Go `Document`, so upstream code must only use authenticated, immutable published package snapshots. Treat this output as diagnostic test evidence, never authorization.

Senior adversarial game-engine-architect source review plus all six exact-head GitHub Actions checks are required for this child. No required check may be bypassed. The iPhone/iPad smoke and physical GPU/thermal gates of the parent Epic #202 remain OPEN.
