# Epic #202 — Cross-language pure semantic tap-score goldens (#436)

The checked-in versioned JSON source `tools/playtest/fixtures/runtime-tap-score-golden-v1.json` is consumed independently by `internal/semanticreplay/tap_score_golden_test.go` (Go) and `tools/playtest/runtime-tap-score-golden.test.mjs` (Node). Neither implementation generates the expected result for the other at test time: each must match the reference output in the JSON file.

Cases: empty input, one positive tap, two taps in the same fixed tick with zero-based ordinals, negative score across separate ticks, identical commands with a different seed, win terminal that stops later same-tick and later-tick commands, explicit lose terminal, zero-score tap. Both consumers require full deterministic repetition, bounded seeds/ticks, integer deltas, terminal state and number/order of commands applied. Go tests input edge balance (pointer down/up, strict canonical `replaytrace`), IR admission and explicit `attested:false, evidenceStatus:unverified, rankingScope:none`. JavaScript uses the **preinstalled, renderer-free** `runtime-semantic-state-reducer.mjs` and maps each canonical tap **down** into ordered `add_score` then optional `end_game` commands; the `up` edge is protocol balance but not another scoring rule. The Node consumer runs as part of the standard Playability test suite.
