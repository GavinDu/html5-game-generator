# Preinstalled bounded semantic input v2 recorder — future player adapter

Parent [Hephaestus Epic #202](https://github.com/GavinDu/Hephaestus/issues/202), [semantic input v2 producer/HTTP ingestion #381](https://github.com/GavinDu/html5-game-generator/issues/381), [diagnostic HTTP preflight #423](https://github.com/GavinDu/html5-game-generator/issues/423), independently scoped [#425](https://github.com/GavinDu/html5-game-generator/issues/425).

This independent, data-only module `internal/api/web/runtime-semantic-input-v2.mjs` provides `createSemanticInputV2Recorder(publishedIRInputBindings, maxEvents)` with an explicit `record({tick, action, device, phase, position})` and `finish(durationTicks)`. The Go API serves the same preinstalled module at `GET /web/runtime-semantic-input-v2.mjs` as JavaScript with `nosniff`; no executable source is permitted inside generated Game IR assets.

The module mirrors the pure Go `replaytrace.Trace` v2 edge vocabulary: only declared `tap`, `drag`, `keyboard` semantic actions; bound UTF-8 action length, no ambiguous same-action tap/drag binding; deterministic nonnegative fixed ticks 0..108000 and consecutive zero-based ordinals per tick; explicit `down`, `move`, `up`, `cancel`; pointer down/move includes integer 1/1000-pixel coordinates within +/-1 billion, keyboard and release omit position; `move` only for a held declared drag; release requires a prior down. The recorder is one-shot: it never infers an unknown pointer action or synthesizes a missing release. Invalid input, backwards ticks, excessive 2000 events, incomplete held-state finalization and oversized JSON permanently mark the trace incomplete without dropping an already recorded prefix. No wall clock, float simulation input, RNG, networking, score, win or browser verification bit is emitted.

Required browser/Node tests assert true v2 wire ordering, same-tick ordinals, multi-action holds, cancel, bad action/control, stuck contacts, zero and edge coordinates, duration bounds, duplicate presses, backwards steps, event overflow, separate game restarts, and unsafe binding/budget rejection. The Go HTTP route test asserts correct module MIME/nosniff and absence of dynamic evaluation.

## Senior game-engine architect challenge / rollout dependencies

**This module is intentionally NOT imported into shipping `pixi-runtime.js` yet.** The current live runtime recorder uses historical v1 `{tick,type,detail}`. Future #381 work must map iPhone/iPad DOM and keyboard events to declared Game IR actions, normalize viewport coordinates and pointer contact ownership, populate correct v2 phases and tie every produced trace to the immutable package IR SHA/version, and submit durable input only when the diagnostic v2 admission and backend auth are deployed. No inferred conversion of legacy v1 pointer samples into new semantic action IDs can be trusted.

The client-owned recorder cannot attest any gameplay outcome, even when its syntax matches the strict Go parser or a fingerprint is accepted by #423. Independent Go-owned fixed-step replay, physics/score/win verdict and idempotent verified state are #382/#360; authoritative-only ranking is #402. This module does not change native iOS WebKit bridge, GPU compositor first frame, App Store 4.7 or physical iPhone/iPad thermal/memory readiness.
